# Учёт инвентарных объектов по штрих-кодам EAN13

Программа для генерации уникальных штрих-кодов, печати наклеек 58×40 мм
на термопринтере Xprinter XP-365B и формирования актов
списания/передачи/установки по отсканированным штрих-кодам.

## Установка

1. Установите Python 3.9+ (на Windows — с сайта python.org, отметьте
   галочку "Add python.exe to PATH").
2. В папке проекта выполните:

   ```
   pip install -r requirements.txt
   ```

   Установятся три библиотеки: `python-barcode` (генерация EAN13),
   `Pillow` (изображения наклеек) и `python-docx` (акты в Word).

## Запуск

```
python app.py
```

Откроется окно с тремя вкладками: **Новая наклейка**, **Действия**,
**Проверка базы**.

## Как это работает

### 1. Новая наклейка
Вводите инвентарный номер, наименование и (по желанию) описание, дата
подставляется автоматически. По кнопке "Сгенерировать и сохранить
наклейку" программа:
- создаёт новый **уникальный** штрих-код EAN13 (счётчик хранится в файле
  `counter.txt`, поэтому номера никогда не повторятся, даже если вы
  вручную отредактируете базу);
- сохраняет изображение наклейки в папку `labels/` (имя файла = номер
  штрих-кода, формат PNG, размер и разрешение подобраны под 58×40 мм);
- добавляет запись в базу `inventory.csv`.

### 2. Действия (списание / передача / установка)
Вводите номер штрих-кода (например, сканером-эмулятором клавиатуры —
такие сканеры "печатают" цифры прямо в поле ввода и Enter) — объект
находится в базе и добавляется в список. Так можно добавить сколько
угодно объектов. Затем выбираете действие, при желании указываете номер
документа, исполнителя и основание, и нажимаете "Сформировать документ".
Программа:
- создаёт файл `.docx` в папке `documents/` с таблицей всех выбранных
  объектов;
- автоматически обновляет статус этих объектов в базе (Списан / Передан
  / Установлен).

### 3. Проверка базы
Кнопка запускает проверку `inventory.csv` на:
- повторяющиеся штрих-коды;
- повторяющиеся инвентарные номера;
- пустые обязательные поля;
- штрих-коды с неверной контрольной суммой EAN13 (например, если файл
  правили руками).

## Файл базы `inventory.csv`

Обычный текстовый CSV с разделителем `;`, кодировка UTF-8 (с BOM) —
открывается в Excel двойным щелчком без проблем с кодировкой. Столбцы:

```
barcode;inventory_number;name;description;date_glued;status
```

Файл можно смело открывать в Excel для просмотра/фильтрации — просто не
сохраняйте его при открытой программе, чтобы не было конфликта записи.

## Печать наклеек на Xprinter XP-365B

1. Откройте PNG-файл из папки `labels/` в любой программе для печати
   изображений (штатный "Просмотр фотографий" Windows и т.п.).
2. В диалоге печати обязательно укажите **печать в реальном размере
   (100%, без масштабирования "по размеру страницы")** — картинка уже
   создана точно под наклейку 58×40 мм.
3. Убедитесь, что в драйвере принтера выставлен формат наклейки 58×40 мм.

Если после печати штрих-код и текст оказываются чуть крупнее/мельче
наклейки — откройте `barcode_utils.py` и поправьте значение `DPI` в
начале файла под фактическое разрешение вашего принтера (указано в его
характеристиках или в настройках драйвера; по умолчанию стоит
стандартное для этикеточных термопринтеров значение 203 dpi).

## Формат документов (актов)

Акты создаются "с нуля" по единому шаблону: заголовок (АКТ СПИСАНИЯ /
АКТ ПЕРЕДАЧИ / АКТ УСТАНОВКИ), номер и дата, составитель, основание,
таблица объектов (№, инв. номер, наименование, описание, штрих-код) и
строка для подписи. Если нужен другой вид акта (другие поля, печать
организации, другой порядок столбцов и т.п.) — измените файл
`documents.py`, функцию `create_act_docx`, либо напишите, что именно
нужно изменить, и это можно будет доработать.

## Структура проекта

```
barcode_inventory/
├── app.py              — главное окно (GUI)
├── barcode_utils.py     — генерация EAN13 и картинки наклейки
├── storage.py            — работа с inventory.csv, проверка базы
├── documents.py          — формирование актов .docx
├── requirements.txt
├── inventory.csv         — база (создаётся автоматически при первом запуске)
├── counter.txt           — счётчик для уникальности штрих-кодов (авто)
├── labels/               — сгенерированные наклейки (PNG)
└── documents/             — сформированные акты (DOCX)
```

## Возможные доработки на будущее
- сканирование штрих-кода камерой (сейчас рассчитано на USB/Bluetooth
  сканер, который эмулирует клавиатуру — это самый надёжный и дешёвый
  вариант для такой задачи);
- отдельная кнопка "Печать" прямо из программы (сейчас печать через
  стандартный просмотрщик изображений — самый совместимый способ для
  разных моделей термопринтеров и драйверов);
- история сформированных документов внутри интерфейса.
